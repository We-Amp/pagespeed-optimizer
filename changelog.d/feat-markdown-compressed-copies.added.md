Added: the optimizer stores a brotli and a gzip copy of each page's Markdown copy, compressed once when the copy is derived at the configured `brotli_level` and `gzip_level` (a level of 0 disables that coding, and a copy that would not be smaller is not stored), so a front end can send an agent the compressed bytes without compressing per request. A Markdown copy stored before the upgrade, or a compressed copy evicted on its own, is compressed on the next agent request for it, or when a front end asks for it. C API 1.16 adds the coding choice for an `Accept-Encoding` field (`ps_markdown_select_encoding`), a stored-facts call that checks a compressed copy belongs to the stored page and its plain copy, the coding in the serve request and verdict with its own entity tag per coding (the plain copy's tag is unchanged), the reason `no_acceptable_encoding`, a compress-demand notification flag and the worker's published codings. New worker counters report the copies written per coding, codings not smaller than the plain copy, and the compress queue.
