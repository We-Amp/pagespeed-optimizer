Fixed: with agent optimization on, a request was served the page's Markdown copy whenever its `Accept` header mentioned `text/markdown`, even as `text/markdown;q=0` (which means "not acceptable") or at a lower q-value than `text/html`. The Markdown copy is now chosen only when a client prefers it over HTML: `text/markdown` must be named with a q-value above 0 and above the q-value `text/html` gets (directly or through `text/*` or `*/*`). Equal q-values, wildcards alone and malformed `Accept` headers get HTML, so `Accept: text/markdown, text/html` now gets HTML. The nginx module also reads every `Accept` header line of a request, not only the first. This applies to the nginx module and the ASP.NET Core middleware.
